## 1. 任务面板：会话结束时清单只剩已完成（@local/dsh-todo-nudge 1.2.0 / @local/dsh-task-board 1.2.0）

- 现象（rc.10）：一轮结束后清单仍留一条「检查笔记完整性并汇报结果 · 待确认」。原因是终审把「回复末尾问用户要不要继续」当成任务没做完，而且设计上允许 open 行留在清单里。
- 新约定：**回合正常结束时，清单里只能剩已完成的条目**。
  - 终审判定改为四类：`done`（有证据做完；汇报/说明/检查类只要回复里给了结果就算完成，结尾顺带提问不算没做完）、`drop`（预想的后续工作，移除）、`wait`（必须等用户回答才能做）、`open`（明确要求、无需等用户、却没做完）。
  - `open`：主会话由守护排队「【任务守护】…请继续」，Agent 立即续跑直到做完；**每个请求最多追问 2 次**（rc.10 为 1 次）。
  - `wait`：移出清单，在面板底部写「等你回复后继续：…」。
  - 追问用尽、子智能体、或审计模型无响应时仍未完成的：移出清单，底部用警示色写「未完成：…（已追问 N 次）」，不会伪装成已完成。
  - 清单被全部移出时面板仍显示底部说明，不会无声消失。
- 兼容旧审计输出：`waiting_user: true` 会把 open 行按 `wait` 处理。

## 2. 会话概览面板（新插件 @local/dsh-session-panel 1.0.0）

右侧栏新增「会话概览」页：`Ctrl+'` 或会话标题栏右侧图标呼出，**再按一次隐藏**；也可从右侧栏「+」的页面列表打开。每个会话各自一份，卡片可折叠（折叠状态记忆）。

- **环境**：工作目录与多工作区关联目录。
- **上下文**：上下文窗口占用（`contextPressure` 投影）进度条 + 已用/总量，≥65% 黄、≥85% 红。
- **连接器（MCP）**：逐个 MCP 服务器的健康状态——已连接（N 个工具）/ 未连接重试中 / 启动失败 / 已停用；非正常时有「重新连接」（经插件管理停用→启用该服务器）。上游没有任何客户端接口暴露 MCP 状态，本插件由宿主侧读取插件加载器行与已注册的 `mcp__<server>__*` 工具得出（`GET /api/sessionPanel.mcp`）。
- **插件**：已安装插件包，启用数与异常数，异常包红点并悬停看错误。
- **技能**：本会话可用技能（`remote.skills.list`），超过 6 个时可筛选；蓝点 = 模型可自动调用，灰点 = 仅手动 `/调用`。
- **输出内容**：本会话写入/修改过的文件（宿主投影 `sessionPanelOutputs`，按最近排序，显示相对工作目录的位置、新建/修改次数、时间），点击在右侧栏打开。
- **更改（按项目管理工具，本地 vs 远端）**：
  - 对会话的工作目录和每个关联目录，自动识别 **Git / SVN**；同时存在多个仓库或多种工具时用标签切换，选择按会话记住。
  - **Git**：分支 → 上游（未设上游时自动对比远端同名分支或默认分支，并注明）、远端地址（凭据已脱敏）、↑未推送提交、↓未拉取提交、未提交文件数与 +/− 行数、「与远端整体相差 N 个文件 · +X −Y」、未跟踪/冲突数、上次获取远端时间；逐文件状态徽标与 +/−，未推送/未拉取提交列表。「获取远端」执行 `git fetch --prune` 后刷新。
  - **SVN**：仓库 URL、本地 r 与远端 HEAD r（落后几个修订）、本地修改文件与 +/− 行数、未版本控制文件；「获取远端」执行 `svn status -u` 统计远端有更新的文件。
  - 每个回合结束后自动重读；面板可见时每 20 秒刷新（MCP 每 15 秒），隐藏时不轮询。
  - 宿主路由 `GET /api/sessionPanel.vcs`、`POST /api/sessionPanel.vcsFetch` 都在 Connection 的鉴权围栏内（与官方 deliverables 相同机制），只执行固定的 git/svn 参数、不经 shell、带超时，结果 4 秒缓存，不写会话日志。
- 实测：本仓库识别为领先 `origin/main` 20 个提交、71 个未提交文件（+883 −181）；`D:\huanjing\lingtao.zhang\mdm`（SVN）识别为本地 r36、远端 r37、3 个未版本控制文件。
