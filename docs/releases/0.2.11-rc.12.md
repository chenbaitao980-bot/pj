## 1. 会话追踪面板（新插件 @local/dsh-session-tracker 1.0.0）

- 位置：左侧栏最上层、工作区列表之上（「更多」与「工作区」之间）。标题行可折叠，折叠状态按设备记忆。
- 三组，永远按「等你处理 → 运行中 → 已完成待确认」排列，覆盖所有会话（不只当前打开的）：
  - **等你处理**：会话在等用户回答/审批/确认计划（`pendingInteraction` = question / approval / plan-review），黄点脉冲；悬停显示问题原文、审批理由或工具名。
  - **运行中**：会话或它的子智能体仍在跑，蓝点；右侧显示最近更新时间。
  - **已完成待确认**：回合在会话不处于前台时结束、用户还没打开查看（`completionUnread`），绿点；打开该会话即视为确认并移出。
- 点击任意一行直接切到该会话（`uiWorkspace.openSession`）；回答完问题后该会话自动转到「运行中」。
- 归档 / 空白 / 子智能体子会话不列出；没有需要关注的会话时标题行显示「全部空闲」，内容区隐藏。
- 数据全部来自客户端根投影（`sessions.list`、`uiSession.sessionStatus`、`workspaces.list`），没有新增宿主路由，不写会话日志。
- 侧栏补丁 `patch-session-tracker.js`：在 `dsh-client-ui-sidebar` 的根插槽上声明子洞 `sidebar.tracker`，并在工作区浏览器之前渲染它（仅宽侧栏；56px 轨道不渲染）。

## 2. 待回答置顶提醒窗（桌面壳补丁 patch-desktop-attention.js）

- 会话进入「等你处理」时，如果主窗口不可见、最小化或没有焦点，在屏幕右下角（主窗口所在显示器的工作区）弹一个 360×148 的置顶小窗：
  - 第一行：`等待回答 / 等待审批 / 计划待审`；
  - 第二行：会话名；
  - 第三行：问题原文或审批理由（最多两行，截 240 字），无则「回到该会话继续处理」；
  - 按钮：`稍后`（关闭）、`查看会话`（打开会话）。
- 用 `showInactive()` 显示，不抢当前应用的键盘焦点；点「查看会话」才还原/前置主窗口，并把会话 id 发回渲染进程直接打开该会话——问题卡就在输入框上方等待回答。
- 点「稍后」、聚焦主窗口或 60 秒超时都会关闭；窗口在前台时不弹（避免打断）。
- 为什么不用 Windows 系统 Toast：微软要求应用具备带 AppUserModelID + ToastActivatorCLSID 的开始菜单快捷方式，本安装器不注册这些标识，Toast 可能静默不显示；自绘置顶窗不依赖注册，跨机器确定可见。纯 Web / 手机端没有桥接，自动降级为面板提醒。
- 桥接：`preload-app.cjs` 暴露 `dshDesktop.attention.notify(request)` 与 `onOpen(listener)`；`main.js` 处理 `dsh-desktop:attention-notify`，`assertProductSender` 校验来源，`will-navigate` 接住 `dsh-attention://open|dismiss`。桌面 main 的 electron 导入补上 `screen`（用于定位显示器工作区）。
