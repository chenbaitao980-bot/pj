## 相对 0.2.11-rc.2 的改动（均来自本轮审计）

### 1. 待办面板 v2：按「进行中集合」重新展开 + 无障碍修正

- rc.1/rc.2 用的是布尔 `hasActive`，只在 `false→true` 时重新展开；如果面板被手动收起、随后进行中的任务从 A 换成 B（布尔始终为 true），面板不会重新展开。
- v2 改为 `activeKey`（所有 `in_progress` 条目的内容串），集合一变就展开。
- 行尾状态文字原本已有同文案的 `role="img"` + `aria-label`，新增的可见文字加 `aria-hidden="true"`，读屏不再重复播报。
- `patch-todo-panel.js` 现在能识别三种输入：已 v2（跳过）、rc.1/rc.2 的 v1（就地升级）、未打补丁（全新应用）；且会在 marker 存在但第二处编辑丢失时报错退出，而不是假成功。

### 2. 构建流程补齐（避免下一次换上游时漏补丁）

- `Build-FrozenSetup.ps1` 现在在 purge/冻结补丁之后自动运行 `patch-todo-panel.js` 与 `patch-slash-plugin-group.js`，再跑 `scripts/verify-install.ps1`；校验不通过直接中止打包。
- 同步阶段新增「repo `plugins/` 下的本地插件逐个 `ship-plugin.js`」步骤，重建时不再需要手工先 ship；`-Version` 改为必填，去掉 `0.2.2-rc.1` 的默认值。

### 3. 安装/升级回执版本号修正

- `install.ps1` 与 `Upgrade.ps1` 的 `version` 不再硬编码 `0.2.2-rc.1`，改为读随包的 `FROZEN-BUILD.json`；升级回执的插件清单从合并后的 profile `bundles` 读取并带版本。
- 装机后 `install-receipt.json` 会显示真实版本。

### 4. 「插件」分组只列裸包名（rc.2 已含）

- 过滤 `dsh-purge/redteam` 这类子路径模块与 `file://…` 解析地址，分组从 6 行降到 5 行。
