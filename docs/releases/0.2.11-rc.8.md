本版是 rc.7 的审计收尾版：四项独立审计（任务面板、purge、产物、移动端）的问题全部修入，并以**热更新**方式装机——不重启正在运行的宿主。

## 1. 任务面板（@local/dsh-task-board）

- **子 agent 会话的停止修正**：当前会话本身是子 agent 时，`session.cancel` 会被宿主拒绝（owned by subagent routing）；改为先取 `sessions.subagentAddress(id)`，走 `subagents.interruptByParent`。
- **「停止整个会话」真正停全**：主会话按 owner 快照的 `running` 判断（不再依赖列表行），并遍历所有 `parentId` 匹配且在跑的列表行——没有清单的子 agent 也会被停。
- **下拉健壮性**：agent 少于 2 个时关闭并隐藏浮层；选中的 agent 消失时重置；面板收起时停止错误也会显示；停止失败的提示改为真实错误文本。
- **停止能力按需注入**：`remote.session`/`remote.subagents` 改为动态注入的 store，命名空间缺失时面板照常显示，只是隐藏停止按钮。
- **称呼修正**：主标签改为「当前会话」（子 agent 视图下不再误称主会话）。
- **手机端**：表头可换行、切换按钮可收缩；浮层高度 `min(260px,45dvh)` 且 `overscroll-behavior: contain`；字号跟随 `--dsh-content-font-size`；按钮加大到 28px；浮层改用 `role="menu"/menuitemradio`，Android 返回键可关闭。

## 2. 工作区管理（@local/dsh-multi-workspace）

- **手机端降级**：`pointer: coarse` 时不再调用电脑的系统目录选择器；「添加/更换」置灰并提示「手机端请在电脑操作，或用 /roots add <绝对路径>」；`directoryPicker` 返回 unavailable/unsupported 时也走同一提示。移除目录在手机上仍可用。
- 两个对话框的遮罩加 `role="presentation"`，Android 返回键可正常关闭。

## 3. dsh-purge revert 保全（补齐审计发现）

- `FROZEN_PATCH_SCRIPTS` 扩为 **7 个**（新增 multi-workspace-ui、sidebar-add-tab），覆盖所有冻结界面脚本；`<安装根>/tools` 缺失时把 7 个全部记为 `missing`，不再静默。
- CLI `--revert`：发现逻辑改为 `discover:true`（无 `DSH_BASE` 也能找到桌面宿主）；只有真正 `applied>0` 且无 missing/errors 时才打印「已重打」；missing 单独列出。
- 安装根判定要求目录像冻结版（`tools/`、`FROZEN-BUILD.json` 或 `resources/app/dsh`），避免 web 全局安装误判。
- 脚本超时改为 20 秒并报 `timed out after 20 s`（5 个脚本合计 < 面板 120 秒上限）。
- 报告：命令 / 工具 / HTTP / 卸载 / CLI 均输出 applied + missing + errors。
- `reapply.js` 在 `preserveClientBundles:false` 的还原后也会补打冻结补丁（防御性）。
- 安装与升级额外清理 `profiles/desktop/node_modules/dsh-purge/.git`。
- `purge-stage.mjs` / `mark-applied.mjs` 改为导入仓库内的 dsh-purge，构建不再依赖本机 `~/.dsh` 的插件副本。

## 5. 项目规范（红线）

- `AGENTS.md` 冻结版规范新增第 6 条：**对齐官方版本必须先做 dsh-purge 冲突检查、并把版本与功能清单交用户确认；与 purge 冲突的功能一律不对齐；未确认不得开工**。

## 6. 移动端

- 结论：**不需要重新下载/安装 App**。手机端就是同一套 web 客户端（dsh-mobile 只替换布局），新插件随宿主下发；装好新宿主后在手机上刷新/重开页面即可。APK 0.7.2 与 dsh-mobile 0.8.4 均无变化，下载入口无需改。

## 7. 安装方式（热更新）

- 用 `Upgrade.ps1` 做 staged 更新：合并 `~/.dsh` 插件、把 `resources/app` 放到 `app.next`；**正在运行的函数不受影响**，下次启动由 `Launch.ps1` 原子替换。
