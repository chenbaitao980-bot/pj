## 1. 根因

- 守护为了省 token，用正则 `/(flash|mini|haiku|fast|small|lite|turbo)/i` 在 `ctx.llm.listModels(provider)` 里找**第一个命中项**。`opencode-go` 的目录顺序是 `claude-haiku-5-5` 第一、`deepseek-v4.1-flash` 第九，于是每次审计都打到 haiku。
- 两个模型走**不同的 API 适配器**：`deepseek-v4.1-flash` 是 `openai-completions`（`https://opencode.ai/inference/go/v1`），`claude-haiku-5-5` 是 `anthropic-messages`（`https://opencode.ai/inference/go`）。本机 `~/.dsh/todo-nudge.log` 里 haiku **219 次调用全部空返回**（0.3–0.7 秒、无正文，`unparsed`），同一份日志里 deepseek 每次都正常出 JSON（`ok`）。
- 放大器：回合中的进度审计把回退参数传成 `placeholder`（只有清单还是占位才允许回退），状态校正则写死 `false`。快模型空返回后整轮不再有任何更新，面板就冻在首次规划（`ipppp`：1 进行中 + 4 待处理）。
- 回合结束时终审拿到空返回，`verdicts` 缺失，按兜底规则「进行中判完成、守护规划的 pending 当预想任务删除」收口——日志 `final ... done=1 open=0 dropped=4 ... fallback`，即截图里的「完成 1 项 · 移除 4 条预备任务（审计模型未响应，按规则收口）」。

## 2. 修复（dsh-todo-nudge 1.2.0 → 1.3.0）

- `routesFor` 只返回会话自己的路由（`agent.model.current()`，回退到 `agent.options`），删除 `listModels` 取名与 `routeCache`。规划、进度审计、状态校正、终审一律走主模型；一条主模型调用换一个不会冻住的面板。
- `ask` 去掉 `fallback` 参数与 `routes.slice(0, 1)` 分支（只剩一条路由，回退语义已不存在）。
- `callModel` 读取流的 `finish` 块，把结束原因（`stop` / `max-tokens` / `error: …` / `aborted`）带回日志。空返回现在记成 `empty finish=…`，下次能直接区分「模型空响应 / 超 token / 网络错误」，不再只有 `unparsed`。
- 日志行格式：`progress|status|final <session> via deepseek-v4.1-flash <ms>: ok`。
