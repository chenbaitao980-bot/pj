## 1. 本版目标

本版处理三件事：

1. 修复 OpenViking bridge 在插件热重载后继续持有已销毁 context，导致 DSH 宿主闪退的问题；
2. 按用户要求移除 Qwen 本地 VLM / 3B 离线 fallback，OpenViking 只使用 DSH 当前 agent 模型；
3. 在无 Qwen 条件下做记忆写入与语义召回回归。

## 2. 闪退根因与修复

### 2.1 根因

`bootstrap.log` 在 2026-11-13T04:18:06Z 记录：

```text
bridge request failed: cannot get required service "agentDefaultModel" in inactive context
```

热重载时旧 bridge 仍监听 `127.0.0.1:8082`，但插件 context 已被销毁。`/v1/models` 处理器直接调用 `ctx.agentDefaultModel.currentSelection()`，异常发生在 async HTTP handler 内且没有捕获，形成未处理的 Promise rejection，宿主进程退出。

### 2.2 修复

`plugins/dsh-openviking-bootstrap/index.js`：

- 新增 `currentSelectionOrNull(ctx)`，context 不可用时返回 `null`，不抛异常；
- 已存在的 bridge 在再次 `apply` 时重绑 context：`existing.ctx = ctx; existing.active = true;`；
- `/v1/models`、`/v1/chat/completions` 统一走 selection 守卫；
- 请求处理器整体 `try/catch`：context 已销毁返回 `503 bridge disposed` 或 `503 model selection unavailable (context inactive)`，其余异常返回 `502`；
- 增加 `server.on('clientError')` 兜底；
- dispose 时仅在 `state.ctx === ctx` 时关闭监听，并调用 `server.closeAllConnections?.()`。

回归脚本 `%TEMP%\ovbridge-crash-test.mjs` 验证：

- 正常 `/v1/models`、`/v1/chat/completions` 返回 200；
- selection 抛 inactive context 时返回 503，进程继续存活；
- dispose 后进程退出码 0。
