`历史加载失败：stored session "..." is corrupt: ... SessionFormatError: step/start does not match the open turn and next step`。
一处是**写入端**的问题（dsh-purge 拦截器），一处是**读取端**太严格（整份日志被判废）。两边都修。

## 1. 写入端：拦截器拒绝后宿主又开了一次同号 step（dsh-purge 1.1.91，#209）

- 现场：`session-e740e37b…`（projectManager-portable）。日志里 step 1 结束 1 毫秒后又出现一次 `step/start {turn:1, step:1}`，随后还跟着一条 `system/message`。
- 链路：`dsh-purge/lib/net-scope.js` 的 `parkDenial` 在拒绝时自己写 `user/message + step/start + assistant/message + step/end`，然后返回 `{ kind: "enter", messages: [] }`，指望宿主按「本步无消息」自动收尾。实际还有第二个 `agent/pre-step` 钩子（trellis 会话上下文）把 messages 补了回来，宿主于是继续开本步，而 `phase.step` 还是 0，于是又写了一次同号 step；`system/message` 也因此在会话已有内容之后才写入。
- 修复：禁止句写入成功后返回 `{ kind: "reject" }`，宿主直接把这一轮收成 `turn/end`，不会再开第二步。禁止句没写成功时仍走原来的放行路径（不会把这一轮收成空白）。
- 版本 1.1.90 → 1.1.91，`release-notes.md` 记 #209。

## 2. 读取端：坏日志自愈（`patch-session-log-repair.js`）

- 新补丁 `frozen-build-src/patch-session-log-repair.js`，改 `dsh-session-persistence-jsonl/lib/index.js`，标记 `/*dsh:session-log-repair*/`。
- 触发：当前格式（v4）日志只因 V4 关系校验失败时才启动；`SessionFormatUnsupportedError` 不受影响。
- 两步修复，**不丢事件、不重排**：
  1. 非首位的 `system/message`（宿主规则只认「第一个 surface 节点的系统消息」）原样归档成 `plugin:dsh.session-log-repair/archived-system-message` 这条 ignorable 记录，seq、时间、完整载荷都保留，只是不再进入模型可见的 surface；
  2. 回放 turn/step，把漂移的 `turn`/`step` 坐标改回连续编号（step/start、step/end、assistant/message、tool/call、tool/result、llm/retry、compaction 等一并跟着改）。
- 重排后仍不合法时，退化为「保留最长可读前缀」。
- 写盘前先把原始字节存为 `<日志>.corrupt-<时间戳>.bak`，再用临时文件 + `MoveFileExW(REPLACE_EXISTING|WRITE_THROUGH)` 原子替换；只在拿到该会话写锁时执行，被其它进程持有写锁时不动文件、保留原报错。
- 打包流水线已加入这个补丁（同步到 `tools\` + 构建时执行），`verify-install.ps1` 新增 `patch: session log repair (stored log heals)` 与 `tool: patch-session-log-repair.js` 两项卡门。
