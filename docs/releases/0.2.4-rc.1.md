## 相对 0.2.3-rc.1 的改动

新增插件 **`@local/dsh-multi-workspace`（多工作区）**：

- `/roots add <绝对路径>`：把一个额外工作区目录挂到**当前会话**上。
- `/roots list` / `/roots remove <路径>` / `/roots clear`：查看与维护。
- 挂上之后，Host 侧 `systemPrompt.section` 会在下一次模型请求时注入「关联工作区」段落，列出全部绝对路径，并说明越界写入需要「完全权限」。
- 不改变会话的 `cwd`，不需要新建工作区，不影响侧栏分组。

沙箱实测（真实 UI 点击验证）：

```
/` 菜单                      → 出现「roots 管理本会话关联的额外工作区（多工作区）」
/roots add D:\dsh-test-root  → 已关联：D:\dsh-test-root 下一次模型请求起生效。跨工作区写入需要在「完全权限」模式下进行。
/roots list                  → 本会话的额外工作区： - D:\dsh-test-root
```

已知限制：roots 存在 Host 进程内存里，重启后需要重新添加；跨工作区写入受当前权限模式约束。
