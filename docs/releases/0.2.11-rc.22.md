# 0.2.11-rc.22

构建时间：2026-11-12 17:39:32 +08:00

SHA-256：`4F42FCAE7BF92D53001EF9ABA24B8FE9F0599F2FD3B87F5210E29F411AE43951`

本版把 `Ctrl+;` 副会话从「fork 一个独立 Session」升级为 Claude Code 语义的
「共享主会话记忆的单向副会话」：副会话能看到主会话后续产生的对话与工具结果，
主会话永远看不到副会话内容。

## 1. 根因

- 旧实现用 `sessions.fork()` 打开副会话。fork 只复制打开瞬间的历史前缀，之后主、副
  两个 Session 各自演进，互不同步——所以副会话聊几轮就「失忆」。
- `sessions.fork` 的 RPC 只写 `isSeeded/agentPreset/cwd`，**不写
  `header.parentSession`**，Host 无法从 Session header 判断「谁是主会话」。
- Claude Code 的 side chat 不是新 Session，而是在同一份 transcript 里写
  `isSidechain:true` 分支；主上下文和 `/resume` 列表都会过滤 sidechain，因此副会话
  共享记忆而主会话不被污染。

## 2. 实现

### Client 半（`plugins/dsh-side-chat/client.js`）

- fork 成功后把副会话标题改成 `⧉ <mainSessionId> · <title>`。Host 只靠这个标题
  找到主会话，不依赖 `header.parentSession`。
- 右侧 tab 标题用 `sideTitleText()` 去掉 `⧉ <id> · ` 前缀，界面仍显示人类可读标题。
- `Ctrl+;` 重开一个已关闭的旧副会话时也会补 marker，旧的无标记副会话自动升级。
- 重命名使用 `sessions.retain(sideId)` → `reference.ready` → `binding.session.rename()`
  → `release()`；8 秒超时，失败只告警，不阻塞 tab 打开。
- 重开旧副会话时保留它自己的标题（`sideTitleText` 去掉旧 marker 后再写回），
  不会被主会话标题覆盖。

### Host 半（`plugins/dsh-side-chat/index.js`）

- 注册 `agent/pre-step`（`{ prepend: true }`），在 `next()` 之后、模型请求之前注入。
- `parentIdOf()` 读 `sessionTitle.get(session)`，解析 `⧉ <id> · `，按标题
  `eventSeq` 缓存；标题被改名后自动失效。
- `lastSyncedSeq()` 从 `session.inheritedEventCount` 起扫描副会话自己的
  `side-chat-memory` 消息，取 `source.parentTo` 作为已同步游标。
- `parent.snapshotEvents(from, parent.seq)` 取主会话增量，只渲染：
  - `user/message` 且 `source.kind === 'user'`
  - `assistant/message`
  - `tool/result`
- 半开游标：`parentTo = 最后消费事件 seq + 1`，下一 step 从该 seq 继续；重复 step
  不会重复注入，预算 16000 字符，超预算下次继续补齐，不丢事件。
- 跳过 `surfaceOp: { op: 'replace', startSeq, endSeq }` 覆盖的事件，避免把主会话
  已经折叠掉的旧消息重新复活。
- 生成一条 `source.kind = 'side-chat-memory'` 的隐藏 user message，外层包
  `<side-chat-memory>…</side-chat-memory>`，明确「这是主会话共享上下文，不是新指令」。
  该消息插在当前用户提问之前，保证用户当前 prompt 仍是模型最后读到的 user 消息。
- **不使用** `source.kind = 'runtime-context'`：agent-loop 会把该 kind 的消息替换成
  自己每步新生成的 runtime context，注入内容会被吞掉。
- 单向：主会话不注册对应的反向注入，副会话内容不会回到主会话。

### 2.1 副会话独立命名与树状显示

- 新建副会话不再复制主会话标题，按 `副会话 N` 递增命名；标题仍编码为
  `⧉ <mainSessionId> · 副会话 N`，Host 继续用它识别父子关系。

  - `nestSideSessions()` 把副会话直接排到父行之后，递归支持嵌套副会话；
  - 副会话行加 `↳` 前缀与 18px 缩进，隐藏状态点与「已完成/待确认」文案，只保留时间；
  - 重命名副会话时自动补回 `⧉ <parentId> · `，不会因为改名丢掉共享记忆；
  - 搜索结果标题也去掉 `⧉ <id> · ` 标记。
- 右侧 tab 标题继续用 `sideTitleText()` 去标记，显示人类可读的独立名字。

## 3. 行为与兼容

- 旧的无标记副会话：`Ctrl+;` 重开时自动补 `⧉ <mainId> · `，Host 从
  `inheritedEventCount` 之后开始同步，不会重复历史前缀。
- 空白主会话 / fork 不可用：仍走 `sessions.create` fallback，Client 同样补 marker；
  Host 从 seq 0 开始同步（主会话本身通常为空，开销可忽略）。
- 嵌套副会话：在副会话里再按 `Ctrl+;`，以当前副会话为主会话，形成单向链；
  `side-chat-memory` 消息不会再次被渲染，避免递归膨胀。
- 手动改写副会话标题会丢掉 marker，Host 停止同步；这是显式退出共享记忆的方式。
