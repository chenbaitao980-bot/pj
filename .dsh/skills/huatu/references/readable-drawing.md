# 可读布局与信息密度

适用于本地可编辑图，借鉴 archify 的留白、分区和碰撞检查，不把整图渲染成一张不可编辑图片。

## 先分清内容，再布图

- 复杂业务默认先画业务主流程，节点用短动作、明确判断或业务结果表达，例如“选择同步范围”“资料是否完整”“通知相关人员”。接口地址、字段名、源码类名、配置键和调用链不写进业务画布的标题、节点正文或连线标签。用户明确要技术流程图、架构图时，按技术图组织；不把这项默认规则套到思维导图、专业建模图或所有图片。
- 主流程只放动作、判断、结果；证据、公式、待确认收入、风险和来源完整保留到详情。用户要求详情绑定建模面板时，详情进入目标画布的真实建模记录，画布只保留必要的业务提示，备注作补充；未要求建模时，可按图的用途设置独立说明区。不要用长便签替代清晰的流程结构。
- 多个系统用独立分区，标题在该区上方；主流程一致向右或向下，返回线走区外独立通道。
- 使用对应专业图库元素；需要资源图标时先查询资源目录，组件用于真正重复的业务结构，不为展示功能硬塞无关符号。

## 业务流程图的详情取舍

- 主线展示业务从什么条件开始、由谁做什么、根据什么结果进入下一步。判断分支用业务条件说明去向，异常分支写出补齐资料、重试、人工处理或结束等实际处置；不以代码函数或异常类型代替业务含义。
- 细节按“业务含义、执行规则、异常与边界、来源依据”组织。源码文件、类名、字段及配置可写入建模记录的来源或规则字段，便于追溯；画布节点保留业务名称。
- 用户要求全部绑定时，每个业务步骤、判断和异常节点都要有可读回的真实记录绑定，不能只给流程标题或几个主节点绑定。节点较多也要逐项核对覆盖；建模记录的数量不能代替节点与记录的对应关系。
- 重画前保留完整 `read`。先把原画布有用的说明、规则、异常和来源迁入对应记录并读回确认，再精简画面；不把移出画布的内容当作可以删除的信息。未涉及的业务内容与已有有效绑定继续保留。

## 先选密度，再定尺寸

- **思维导图、功能树、需求清单**：正文先用 18–20px，主分支 22–26px，中心主题 28–32px。节点按实际文字宽高确定，左右各留 12–20px、上下各留 8–12px，并遵守节点渲染器的最小尺寸。短主题不要一律套 300px 宽的大卡片；长说明通常用 320–440px 宽并换行，增高到文字完整显示，不靠缩小字号塞入。
- 这类树图的兄弟子树间距先取 12–24px，父子横向间距 40–80px；按子树所需高度递归排列，父节点居中。各分支按自身节点宽度推进，避免全图按最长说明统一拉宽每一列。保留原分支顺序与完整内容。
- **流程图、跨系统图**：正文先用 16–20px，节点通常宽 220–320px、高 80–140px，按文字量调整；同层间距可从 48–96px、相邻层 80–160px 起步。判断、返回线与边标签按实际需要增加通道。演示或强调分区时再采用更大的节点与留白。
- 这些数值是可调起点，不是全部图的固定下限。用户要求“紧凑”时先缩短空白、收紧节点与分支；用户同时指出“字小”时应提高正文可读字号。只改 `layout.spacing` 或缩小画布范围不足以完成调整。
- 字号使用数字字符串（例如 `"20"`）。`text` 节点需要固定字号时同时设 `data.textScaleWithNode:false`；否则沿用产品按文本框面积缩放字号的行为。节点宽高、字号、换行一起计算，检查实际渲染是否裁字。
- 注意渲染器差异：当前普通 `process` 圆角节点即使保存较小的 height，无图标/副标题时实际最小高度仍为 84px；几何检查不能只相信 read 中较小的 size。原生 `mindmap` 节点已改为按 `data.fontSize` 渲染（不再固定 14px），新增主题继承可读字号；仍要核对有效屏幕字号（节点字号 × 缩放）：正文 ≥16px、次要说明 ≥14px。不要把写入一个字段当作其视觉效果已生效。`text` 节点的字号默认随框放大（最多 ×3），宽标题框会把 22 渲染成 66px 并溢出压住下方内容：一律写 `textScaleWithNode:false` 和明确字号，框高按行数留够（见 SKILL.md 规则 24）。
- 验收同时查看全图和 80–100% 局部。大图的全图视图用于看结构，局部用于读文字；不要靠“缩放至全图”掩盖节点空白过大或正文过小。

## 连线

- 普通可折叠思维导图用有向连线表达主题→子主题，再切换 mindmap 视图；非树关系以辅助线保留。该视图会重新投影位置与走线，不能用保存的 canvas 坐标检验其显示密度。用户要求精确间距或直角分叉时，可在 canvas 中自定义紧凑树形排版。不要为单纯切换视图执行 layout。
- 流程图自动布局可按目标密度选择 `compact/normal/loose`，并使用 `readability:true` 保留折线与标签空间。不要对思维导图机械执行 LR + loose；原有大节点也不会因 spacing 改为 compact 自动变得合适。
- 自定义排版用 `waypoints` 指定完整折线路径。相互独立的返回线使用不同通道，间距建议 ≥32px；不要多条线共用一条长水平干线。
- 起终点的实际锚点与第一/最后一段方向一致。不要把本地绘图库句柄命名规则猜成通用端口；读取现有节点或使用目录条目实测。
- 对已确认的右出左入树图，路径从父节点右侧实际锚点出发，经节点间空隙中的竖向分流线到子节点左侧锚点。可以共享同一父主题的树干，保留每条父子关系；独立业务流程仍需分开通道。路径在横向上应持续前进，检查源节点附近是否出现无必要的反向小段、U 形回绕或多重圆角团。
- `smoothstep` 的圆角本身不等于回绕原因。ELK 分配的端口位置与渲染器实际句柄不一致、旧路径未随尺寸/位置更新，都可能造成回折。用户指出这类问题时重算完整路径与端点；只把 smoothstep 改为 step 可能保留同一团折线。移动、缩放、改字号引起节点尺寸变化时，在同批中同步更新受影响路径。
- 连线文字以 16px 为默认起点，较密集的图可按实际效果调整：有标签的 `add_edges` 和 `add_reference_edge` 显式设置 `labelFontSize:16`，旧版桥先查能力并实际核对；检查 80–100% 局部和实际缩放下的可读性。
- 标签放在足够长的直线段，`labelPosition` 调整沿路径位置，`labelOffset` 将文字推到空白处，避免压线、贴节点、互相遮挡。节点与标签间建议保留 20px 以上。
- 连线颜色表达同一种语义：中性主流程、绿色可持续/通过、橙色待确认、红色风险/返工；颜色不代替文字含义。

## 交付前检查

1. read 复核每个原有业务节点、连线含义、风险说明、来源均保留；迁入建模的内容用 modeling_read 核对。重画可变更布局与呈现，不能把未证实收入改成事实。
2. 检查节点矩形相交、标题落入节点、线穿过无关节点、长共线段、标签对节点和标签的碰撞；发现后调整再读回。
3. 实际打开目标图，检查全图结构、最长文字节点和分支最多节点的局部。确认文字可读、框内空白合理、同屏能看清一组相关分支，节点出口无回绕。报告字号、间距或局部效果等与用户问题直接相关的结果；节点数量正确、零矩形相交或外包框缩小均不能替代这些检查。
4. 无法获得实时画布截图时，可用完整 read 数据生成布局预览检查文字与路径，并明确这是数据预览；不要声称完成了实时界面视觉验收，也不要将界面通道不可用转述成用户已经满意。
5. 需要验证其他能力时，让资源图标、笔迹强调、可复用组件、建模记录分别承担与业务有关的作用，逐项读回验证。
6. 有“全部绑定”要求时，逐个核对业务步骤、判断和异常节点的绑定及其真实记录，检查业务含义、执行规则、异常与边界、来源依据是否完整。读回关键中文正文，确认没有问号替换、乱码或截断；节点数、记录数和保存成功均不能替代内容验收。

## 用户要求功能验收时

- 用户明确要求多用画笔、专业图形或全面检查技能时，在同一画布设置独立验收区，按类别排版，并写明模板示例与实际业务的边界。无需新建多张画布，也不要把示例数据写成实际收益。
- 画笔应实际覆盖 pen 和 highlighter，以及颜色、粗细、透明度和压力；可展示圈注、括号、箭头、勾选、波浪线和叠色。每一笔均用 add_ink 创建，不能用图片、SVG 或普通连线冒充笔迹。正式业务图只保留有用的强调，充分演示放验收区。
- 图形从当前 catalog 选取多种专业条目，例如 BPMN 事件/活动/网关、E-R 实体/关系/属性、UML、SysML、EPC、价值链、表格、图表和线框；按条目实际原生类型验收，不要求它们全部成为 libraryShape。
- 写后统计并读回新增笔迹、专业图形类别、路径和绑定；碰撞检查也包括 text 节点的矩形范围，避免漏掉穿过副标题的返回线。实际查看整体结构和关键局部，不把保存成功等同于全部视觉验收通过。

## 导图模式阅读检查（2026-10-27）

- 导图投影默认父子间距 52、兄弟间距 12，按每个父节点实际宽度推进；超过 40 个可见主题的导图首次进入先看主干概览，再展开分支阅读。全图总览只用于看结构，正文可读性以阅读视图的有效屏幕字号为准。
- 同级顺序取决于父节点出边在 edges 数组里的顺序；用 `add_edges` 按阅读顺序写入，不要依赖节点坐标排序。
- 边界、概要、关系线、备注/链接/标记在导图和画布模式都要检查：边界包住的成员是否连续（兄弟边界）、概要是否可编辑、关系线是否未改变两端父子关系。详见 SKILL.md。

## 泳道图（2026-11-02 用户定规，已四次纠正）

- **对象竖向排列：每个对象一整列，对象名作表头放在最上面，流程从上往下。** 不要画成左侧横条。
- **泳道底色必须整列覆盖元素范围**：每个对象一个 `swimlane` 节点，从顶部表头一直铺到该列最后一个元素下方约 50px，同批里最先创建（最底层）；列与列并排相接，不画虚线分隔，不能只有顶部一条表头。
- **图层**：泳道节点必须在连线和节点下面（`zIndex:-1`，桥已默认）；泳道图层太靠前会挡住连线，只在泳道空隙里露出线。
- 每个业务步骤都要有连线：同列向下，同一步跨列交接用水平线并写交接对象；资金流紫色、合规检查点橙色虚线、返工回退红色虚线。
- 一张图的元素接近 50 个就拆成原子泳道图，用聚合图引用，模块之间的业务关系用带标签的跨画布连线表示。
- 每个业务节点绑定建模记录（步骤、对象、业务含义、执行规则、异常与边界、来源依据、等级）。
