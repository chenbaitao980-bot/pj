# 运筹蛊本地画图（命令桥）

本技能把类型化命令发给工作站后端，由**正在运行的工作站主窗口**操作本地画布。停留在首页、存石蛊、司时蛊等页面即可使用，无需先手动打开画布；读取不跳转，写入时自动打开准确的目标画布。一次 `apply` 是一个撤销步骤，保存后读回校验，失败整批回滚。面板控制、组件库保存与建模数据通过独立 `tool` 命令执行，不能声称可用画布撤销恢复数据库。

出图或整理布局前阅读 [画法与检查规则](references/readable-drawing.md)。涉及工具栏功能时阅读 [面板、资源、组件与建模](references/editor-tools.md)。不要把“能打开面板”当成“已完成数据操作”。

复杂业务的流程梳理默认画业务主流程，用短句表达动作、判断与结果。接口地址、字段名、源码类名、配置键和代码调用链放入详情；用户明确要求技术流程图、架构图等时，再按技术图表达。思维导图、专业建模图和其他图片仍按各自用途处理。

用户要求“细节全部绑定建模面板”时，为目标画布内每个业务步骤、判断和异常节点保存真实的建模记录，再用 `bind_record` 绑定。备注只作补充，打开建模面板或填写 `data.notes` 均不等于完成绑定。详情组织、原图信息迁移及逐节点验收见 [面板、资源、组件与建模](references/editor-tools.md#业务节点详情与真实记录绑定)。

## 大型复杂业务：系统、原子功能、聚合图（用户确定的设计）

目标是高内聚、低耦合：每项逻辑只在一个地方维护，其余地方引用它。

### 1. 分组（首页文件夹）
- **默认不建文件夹、不 `organize`**：新画布建好后留在首页「未分组」即可，不主动归类、不猜归属。只有用户明确说了要放进某个文件夹（系统/项目/聚合图），或这张画布需要被别的画布引用，才执行 `organize`。用户后续要求移动时，按他给的路径 `organize`。
- **系统 = 首页文件夹**，如 `工作 / 九洲 / houduan1 数据同步服务`、`工作 / 九洲 / OA 系统`。系统下面放的是原子功能画布。
- **聚合图** 放在独立文件夹 `工作 / 九洲 / 聚合图`。
- 不建“系统画布”“外部系统边界画布”这类壳。外部系统没有源码依据就不画内部逻辑，在聚合图里画成普通方框。
- 需要被引用的画布必须在建好后 `organize` 登记并放进文件夹，否则引用面板里选不到。

### 2. 原子功能画布
- 一张只维护一项相对独立的业务流程与规则；小步骤不能独立理解时可合并，不按代码类机械拆图。
- 自包含：不引用别的系统，原子画布之间不互相引用（避免循环）。
- 画业务主流程：节点用业务短句，接口、字段、类名放详情；细节绑定建模面板（见规则 12）。
- 图形：判断菱形用 200×200 正方形、字号 16；行距 ≥260；线必须贴合图形（菱形等外框会被规整成正方形）。
- 建之前先查是否已有同职责画布，有就更新，不重复画（规则 11）。
- **归属哪个系统**：一个功能涉及两个系统时，看哪边系统占比多就放哪边；占比相当就放发起方；只放一处，不重复画，另一系统的聚合图用引用。

### 3. 聚合图（如“数据同步”“采购”）
聚合图是一种设计思想：**只要一张画布引用了原子画布，它就是聚合图**，不分大小；命名用“XX 聚合图”或功能名，不叫“聚合图”。
- 不重画流程，只**引用**不同系统文件夹里的原子画布，再用关系线连起来。
- **系统边界竖向并列，用“边界”而不是泳道节点**：一个系统一列，从左到右按数据流排（来源 → 主数据 → 同步服务 → 目标系统）。每个系统一个边界（`canvasBoundaries`，和编辑器工具栏的“边界”是同一个功能，颜色、样式、标题都能在边界面板里改）：先在列顶放一个本图的文本节点写系统名，它作为边界的 owner，边界成员写 `[owner, 该系统的本图节点…, "ref:<引用id>"…]`，引用卡片用 `ref:` 前缀的引用 id 圈进去。列宽 ≥480，列间留 ≥220 的走线通道。不要用 `swimlane` 节点当系统边界：它不会随展开变大，而且删除泳道会连带删掉里面的子节点。边界会贴着成员，展开引用时自动长大，整列（含边界里的节点和卡片）作为一个整体让位，所以各列始终对齐。
- 数据来源或汇聚点（主数据、EHR 等）没有原子画布时，画成本图的普通节点。
- 引用默认 `collapsed:true`（折成 340×120 的卡片，卡片上不写备注）；引用的是**展开的子聚合图**时不能按卡片留位，见规则 23。原子画布的引用按折叠尺寸留位，展开时周围元素和其他列里下方的节点会自动让开，泳道自动变大（只是显示，不改保存坐标）。
- 关系线：用 `add_reference_edge`，端点连到原子画布里的**具体步骤**；一律显式写 `sourceHandle`/`targetHandle`（左列→右列 `right`→`left`，反向相反）；同方向多条线不共用同一对端点；标明真实数据方向和业务含义；待核实的用橙色或虚线。

### 4. 引用的行为（理解后再画）
- 引用是**镜像不是链接**：被引用画布的内容真实显示在聚合图里，原画布改了聚合图同步变；只放方块或文字链接就是做错了。
- 折叠时连线落到卡片；展开后，指向内部步骤的长线先接到子图边框上的接口点（与步骤同高），再用短虚线连到该步骤，所以长线只走在列间通道里。
- **跨系统的线必须连到系统里的具体元素**（`add_reference_edge` 的 `object` 写步骤节点 id），不要只连到引用本身；折叠时线落在卡片上，展开后线先接到子图边框上的接口点再连到该元素，所以展开不会让线消失。
- **展开后自动重排**：某个系统因展开变长时，其他系统里的节点会自动移到它们所连元素的高度，边界跟着变大，线保持水平、短而直（只是显示，不改保存的坐标，折叠即复位）。排版时仍按折叠卡片留位。
- **折叠展开与跳转**：引用框标题旁有 `▸/▾`（折叠/展开）和 `↗`（打开被引用的画布）两个小图标，鼠标移到标题或选中该引用时才出现，并且随画布缩放一起变小；引用面板里也有“打开”“全部展开/全部折叠”，双击镜像节点同样跳转。
- **删除保护**：原子画布里被聚合图连线引用的元素**不能删除**：在编辑器里删除会被拒绝并提示被哪些画布引用、几条线（同时删多个时，只保留被引用的那些，其余照常删除）；桥命令的 `delete` 也会拒绝并报“cannot delete elements used by other canvases”。需要删除时先到聚合图里改掉相关连线。
- **建模数据按业务归属分布并绑定**：先检查原图的建模记录及元素、连线绑定，按业务含义把记录放在对应的原子画布或聚合图本身；原子画布的节点和连线绑定该画布作用域内的真实记录，跨系统关系属于聚合图的则绑定聚合图内对应连线。聚合图通过“建模来源”查看引用画布的记录，禁止把原图所有整表机械复制到聚合图，也不要把原图引用进聚合图。迁移前列出原记录、来源、目标画布和元素或连线的映射；保留原图不动，核对记录内容与绑定后再清理目标图中确定多余的副本，不能删除不明归属或其他画布的数据。模型、记录、绑定逐项读回核验；复制工具仅在用户明确要求整表副本时使用，附件共享和分组限制应事先说明。
- 引用只能加在已存在的画布上（`--create` 的批次不能含引用）；同一个 `ref id` 在整个库里必须唯一，建议 `<聚合图>:<目标>`；核对目标 ID、层级、循环，不能用普通图形冒充引用。

### 5. 建立顺序
功能（原子）画布 → （需要被引用才 `organize`）→ 聚合图（先建空画布，再追加引用和关系线）。重构已有大图：原图保留，拆成原子画布，再用聚合图引用（规则 12）。改名用 `rename_flow`，删除只在用户明确要求时用 `delete_flow` / `remove_folder`（规则 13）。默认不建文件夹，画布留在「未分组」（规则 14）。

脚本目录：`.agents/skills/huatu/scripts/`（Node 18+，无依赖）。脚本会从工作站 `data/config/runtime-state.json` 读后端端口，从 `data/config/canvas-bridge-token` 读令牌；令牌不得打印、复制或写入任何文件。

## 强制规则

1. **工作站主窗口必须开着，且只保留一个主窗口**：首页、存石蛊、司时蛊等页面均可保持命令桥在线；不要求用户先打开画布。`targets/read/catalog` 可直接使用，`apply` 自动导航到已确认的文档与页面再写入。`tool` 的面板操作在首页时须传 `--doc/--page`，由命令桥打开目标并等待真实面板就绪。独立查看器、进度窗口和建模辅助窗口不注册第二个命令桥。不要在内置浏览器等其他窗口打开工作站页面（http://127.0.0.1:4173）：它会注册第二个命令桥，写入立刻报 `multiple_editors`，关闭后约需数十秒才恢复；该浏览器的存储与主窗口独立，也看不到主窗口的画布。`no_live_editor` 时检查主窗口与版本，必要时刷新或重启主窗口后重试；不要改用远程图或其他方式冒充写入。
2. **先确认目标再写**：写已有画布前必须 `targets.mjs` 列出文档/页面，让名称与用户所指一致；多个候选或同名时列给用户选，不猜。
3. **先读后写**：改已有画布必须先 `read.mjs` 取得 `version`，再把它作为 `--base-version` 传给 `apply.mjs`；版本过期（`stale_version`）就重新 read，按最新内容重新规划，不强行覆盖。
4. **只用目录内的图形**：先 `catalog.mjs`；`shape` / `libraryItemId` / `insert_component.itemId` 只能取目录里存在的值，目录外会被拒绝。不能用统一矩形冒充专业图形（BPMN、UML、SysML、E-R、平面图等要用对应类别的图形）。
5. **保留无关内容**：默认增量添加；不删除、不移动用户没提到的元素；不要用整图覆盖代替新增。
6. **不注入业务绑定与密钥**：图形 `data` 中的 bind、modelId、recordId、凭据等会被拒绝。建模读写必须使用有目标作用域的专用 `tool`；保存个人组件会清除原业务绑定。
7. **失败如实报告**：命令失败、超时或结果未知时，原样报告错误码；超时先 `targets/read` 核对实际状态，再决定是否重试，重试沿用同一 `--key`（幂等，不会重复写入）。写后用 `read.mjs` 复核业务内容、关键中文正文和节点/边数量；有建模绑定要求时，逐节点核对真实记录，不能只凭数量报告完成。
8. 没有明确要求时不要新建多张画布；同一批图形修改尽量合为一次 `apply`。当前每批最多 200 个 op，单条 `add_nodes`/`add_edges` 最多各 500 项；大图需要多批时按完整分支或相邻区域拆分，每批重新 read 并使用最新 base-version，说明会产生多个撤销步骤。工具命令每次一个操作，明确区分画布、组件库和建模数据库的保存结果。重画整图须先保留完整 read 结果。
9. **按图类型选择密度并检查实际连线**：思维导图、功能树使用内容驱动的紧凑节点；流程图或演示图的宽松尺寸不能套用到所有图。用户指出“字小、太散、回绕”时，同时检查字号、节点空白、分支间距与路径端点；仅返回节点/边数量正确或画布面积缩小，不能作为这些问题已解决的依据。具体起点与检查见 [画法与检查规则](references/readable-drawing.md)。
10. **导图表达与信息用现有数据键，且分模式验收**：边界、概要、关系线、备注/链接/优先级/进度在导图模式和画布模式都可用，数据键见下文“导图表达与主题信息”。创建这些内容必须用 `add_nodes/add_edges/update_node/update_edge` 的 `data`（`add_edges` 没有 `data` 字段，关系线要先建边再 `update_edge`）；写后 `read` 核对键与成员 ID，并在两种模式下各看一次，不能因为某一模式显示正常就报告完成。

11. **先查后画，已有就更新**：动手前先 `targets` 列出现有画布，按系统文件夹和名称、职责查是否已有同一功能。已有就 `read` 后增量更新（改节点、补步骤、调整引用），不新建重复画布；聚合图引用前先确认原子画布存在，缺哪张才补哪张。名称相近或职责重叠的画布先问用户是否合并，不要各画一份。
12. **重构已有大图**：先完整 `read` 并另存备份，**原图保留，除非用户明确要求删除**。按业务功能拆成原子画布放进对应系统文件夹，每张只画一项相对独立的流程，节点用业务短句；原图里的说明、规则、异常、来源迁入各节点绑定的真实建模记录（先 `create_model`/`create_record`，再 `bind_record`），逐节点读回核对；原图可再整理成引用这些原子画布的聚合图，但改动前先让用户确认。重构完成后用 `read` 和 `modeling_read` 核对内容没有丢。
13. **删除只走命令并先确认**：用户明确要求删除时才用 `tool` 的 `delete_flow`（移入首页回收站，可恢复；被其他画布引用时会拒绝，先改引用）和 `remove_folder`（只删空文件夹）。不要删用户没提到的画布或文件夹。

14. **默认放未分组**：新建画布用 `--create` 写完即结束，**不要顺手 `organize` 到任何文件夹**。新建画布会自动出现在首页，未指定分组时归「未分组」。只有两种情况需要 `organize`：用户点名了目标文件夹，或该画布要被 `add_canvas_reference` 引用（引用要求目标已登记）。用户说"以后默认放未分组"时以本条为准。

15. **体量上限与拆分（用户定规，所有复杂系统都适用；2026-11-03 第二次强调，聚合图也一样）**：**任何一张画布，包括聚合图，元素总数不得超过 50 个，目标 ≤40，图要清爽。** 元素 = 节点（含泳道表头、标题文字）+ 连线 + 引用 + 跨画布连线，四项相加。写完必须用 `read` 数一遍（`nodes + edges + references + crossGraphEdges`），超了就拆，不许先交付再说。按业务功能拆成原子画布（每张只维护一项相对独立的流程，业务节点建议 ≤30 个），再用聚合图引用原子画布，并用**带标签的跨画布关系线**画出模块之间的业务关系（写明交接对象，如“已签合同”“放款指令”）。发现已有画布超限时：原图保留，先拆再改（规则 12）。聚合图写完后读回核对 `references` 数 == 被引用画布数、`crossGraphEdges` 数 == 业务关系数。**聚合图里可以再套聚合图（见规则 19）**：一张聚合图引用的模块或连线太多，就按域拆成子聚合图，上层只放子聚合图的引用。
16. **泳道图画法（用户定规，已两次纠正，务必记住）**：**对象竖向排列：每个对象是一整列竖向泳道，对象名作表头放在最上面**（买家、卖家、平台、教练、支付机构、监管等各占一列），**流程从上往下走**。不要把对象画成左侧的横条或横向泳道（2026-11-02 用户截图纠正：表头要在顶部）。**泳道底色必须整列覆盖元素范围（用户 2026-11-02 第三次纠正）**：每个对象一个 `swimlane` 节点，对象名作表头在顶部，节点高度从表头一直铺到该列最后一个元素下方约 50px，**图层必须在连线和节点下面**（`swimlane` 节点默认 `zIndex:-1`；旧画布或旧版工作站用 `update_node {zIndex:-1}` 改；2026-11-02 用户第四次纠正：泳道图层太靠前会把连线挡住，只在空隙里露出线）；同一批里最先创建；列与列并排相接，靠底色和边框分列，不再画虚线分隔。只给表头一条窄条而下面空白是错的。同一对象在同一步有多个节点时在该列内并排放（列宽按并排数加宽）。连线：同列向下 `bottom`→`top`；同一步的跨列交接用水平线（`right`→`left` 或反向）；交接到下一步用 `bottom`→`top`；回退线从 `right` 出、绕到 `right` 入。每个步骤必须有连线，跨列的交接写交接对象；除起点和终点外，既无入线也无出线的节点视为漏画。资金流（紫）、合规检查点（橙虚线）、返工回退（红虚线）用颜色区分。只放参与该功能的对象，不放空列。判断菱形按“大型复杂业务”一节的尺寸画，行距要放得下（≥200）。已有横向泳道图要改成竖向时，不要删节点（会丢建模绑定，被聚合图引用的节点也删不掉），用 `move` 改位置、`update_node` 改表头、`update_edge` 改连线端点。
17. **建模面板默认绑定（用户定规）**：每次画图默认给**每个业务节点**建真实建模记录并用 `bind_record` 绑定，记录至少含：步骤、对象、业务含义、执行规则、异常与边界、来源依据、来源等级（A/B/C）；聚合图的跨模块关系线同样建记录（交接对象、触发条件、责任方、规则、依据）并绑定到连线。只有用户明确说“不要绑定”才可省略。写后读回逐节点核对 bound == 业务节点数，不能只凭记录数量报告。**建模记录一律走后端 REST 批量写入，不要逐条走命令桥**（命令桥 `create_record` 每条约 20 秒，REST 一批 <1 秒；2026-11-03 实测 72 条从预计 15 分钟降到 1 分钟）。做法见规则 22。绑定仍走命令桥 `bind_record`，一批最多 20 个。失败后先查已有记录再补，不要整批重跑。
18. **实测坑**：节点 id 只能 ASCII（中文泳道名不能当 id，用 `lane_0` 之类）；`size` 宽高不得小于 8；`--create` 的批次不能含引用（聚合图先建空画布再追加）；Windows 的 Git Bash 没有 `rm`，`rm … && python …` 会让后面的命令静默不执行；后台脚本运行期间不要再调用命令桥写入；`create_model`、`create_record` 必须带 `--base-version`；幂等键失败后换新键（一个批次失败回滚后，同一个键不能再配不同内容重发，会报 `idempotency_key_reused`）。
19. **聚合图分层与第三方对接画法（用户定规 2026-11-03）**：
    - **嵌套连线**：上层画布可以用镜像路径（`ref_子聚合图>ref_原子画布`）把关系线直接连到子聚合图里原子画布的具体步骤；路径上任一层折叠时线落到最近一层折叠卡片上。所以按业务拆子聚合图后，子图之间的关系画在上层图上，不要为了连线在别的聚合图里重复引用同一批原子画布。删除保护、移除引用清线都认路径。
    - **分层**：聚合图可以再引用聚合图，但只在**按业务**拼出更大的功能时才分层（如“采购聚合”+“结算聚合”拼成“交易总图”）；每一层都 ≤50 个元素，子聚合图要先 `organize` 登记才能被上层引用。**不要为同一批原子画布再做一套“换个角度看”的聚合图**（例如把各模块里的第三方再抽成“第三方对接聚合”）：那是重复维护，见规则 26。
    - **第三方对接画在模块自己的泳道图里，不单独成图（用户 2026-11-03 纠正：第三方对接整合进业务流程，删掉多余画布）**：每个功能模块的泳道图里，用到的第三方放在本图的第三方泳道中，与使用它的步骤直接连线；业务流程聚合图引用这些模块，就自然展示了全部第三方对接。不要再建“第三方对接聚合图”或按域拆出的第三方子聚合图，也不要让聚合图里的模块连到一堆第三方节点。
    - **功能（泳道）图里画第三方**：在最右侧追加“第三方”泳道（violet，列宽 370，同样整列底色、zIndex −1），第三方节点 300×130 竖向排布（间距 ≥210），每个第三方节点只写“名称 + 一句关键限制”（≤3 行、每行 ≤16 字），资质、费用、周期全放建模记录。连线从**平台侧或对象侧的具体步骤**的 `right` 出，沿**本列右缘**（列右边界 −12px）下行到**行间空带**（该步骤下沿 +50px，保证与所有节点矩形相距 ≥6px），横穿到目标列左侧 22px，再进入第三方节点 `left`；同一空带上有多条线时每条错开 14px。用 `waypoints` 写出完整折线（绝对坐标），**写入前用节点矩形做相交自检**，不得穿过任何节点。
    - **第三方对接建模表**：建在**使用它的模块泳道图**上（模型名 `<泳道图名>-第三方对接`），每个第三方一条记录，字段至少：第三方、用在本环节、提供方/办理机构、准入条件、所需资质与材料、一次性费用（开通/认证）、运营费用（持续/按量）、办理周期、个人主体能否接入、限制与坑、来源依据、来源等级。**运营费用和一次性费用必须分开列**，查不到写“无可靠数据”，不填估计值。一个第三方被几个模块用到，就在每个模块里各建一条，“用在本环节”只写本模块的用法；同一条记录里补上本模块的对接关系（交接对象、触发条件、责任方、对接规则、依据），绑定到本图的第三方节点**和**步骤→第三方的那条连线。
    - **品类等可配置项**：用户说“后台可配置”的维度（品类、城市等）不要写死进流程图，做成配置表（每个值一条记录：准入资质、平台义务、保险、额外第三方、首期建议、来源等级），绑定到运营后台的配置节点。
20. **改聚合图的实测限制**：`delete` 的 `edgeIds` **删不掉跨画布连线**（报 `unknown_edge`）；要清掉跨画布线只能 `remove_canvas_reference` 把引用移除（连到它的跨画布线一并消失），再 `add_canvas_reference` 加回并重建需要的线。移除前先把要保留的线的 id、端点、标签、句柄、绑定记录 id 存下来；原绑定的记录还在，重建后用 `bind_record` 绑回即可。`add_reference_edge` 的端点不能是 `__summary__`（会报 `unknown_node`），必须是被引用画布里真实的节点 id。`bind_record` 可以绑到跨画布连线的 id 上。`move` 可以挪局部节点；被其他画布引用的节点删不掉。
22. **建模批量写入的快路径（用户嫌慢，2026-11-03）**：后端地址读 `data/config/runtime-state.json` 的 `ports.backend`，无需令牌，在项目根目录执行。命令桥只负责读画布、`create_model`、`bind_record`；其余建模操作直连 REST：
    - **批量建记录**：`POST /api/models/{modelId}/records`，body 是数组 `[{ "values": {...} }, ...]`，返回逐条结果（单条失败进结果集 `error`，不整体回滚）。写之前先 `GET /api/models/{modelId}/records?limit=200`（带 `cursor` 翻页）按唯一字段去重，可重复执行。
    - **改记录**：`PATCH /api/models/{modelId}/records/{recordId}`，body `{ "values": {…只写要改的键…}, "expectedVersion": <读到的 version> }`，只合并传入的键；版本不符返回 409。
    - **给模型加列/改列**：`POST /api/models/{modelId}/fields` `{key,label,type,order?,hidden?}`；`PATCH …/fields/{fieldId}` 可改 `label/order/hidden`；`GET /api/models/{modelId}` 取字段列表。
    - **旧记录里残留已删列的键会让 REST 的 PATCH 报 400「未知字段」**（它校验合并后的全部键，命令桥只校验传入的键）。处理：把缺失的列以 `hidden:true, type:text` 补回再写。
    - **fetch 要带 `connection: close` 并重试**：脚本里用 `spawnSync` 调命令桥会阻塞很久，之后复用的空闲连接会被重置（`ECONNRESET`/`fetch failed`）。
    - 写完仍要用 `modeling_read` 读回核对记录数，再用 `bind_record` 批量绑定，最后对每张图跑一遍“元素数 ≤50、业务节点 bound == 业务节点数、跨画布线 bound == 跨画布线数”的核对。
21. **Windows 上写脚本的坑**：在 Bash/PowerShell 命令里用 `python`/`node -e`/heredoc 写含反斜杠的内容时，命令文本里的 `\n` 可能被提前当成真实换行，导致 JS 字符串被劈成两行、正则报 `missing /`。需要写 `\n` 时，用 Write 工具直接写文件，或在代码里用 `chr(92)` 拼出反斜杠，改完立刻 `node --check` 一遍。

23. **嵌套聚合图按“展开后的真实大小”排版，写完必须跑自检（用户 2026-11-03 截图纠正：系统图叠成一团）**：
    - 下一层引用默认就会镜像显示（按目标画布自己的折叠状态），所以上层引用一个**展开的**聚合图时，它占的不是 340×120 的卡片，而是该聚合图全部内容（含它自己的引用卡片或展开的子聚合图）的外框。按卡片尺寸留位就会叠在一起。
    - 排版：先算每个被引用聚合图的展开外框（宽、高、内容最小 x/y），同层引用之间留 ≥300 的空隙；横排时 `x(下一个) = x(上一个) + 宽 + 300`，竖排同理。并列的子聚合图标题放在相同的相对高度，标题下沿离第一张卡片的框顶 ≥40（被引用原子画布的内容常从负坐标开始，卡片框顶会高于 y=0，要按读回的坐标算）。上层标题放在所有引用框之上 ≥100。
    - 每一层只决定自己这一层的位置：子聚合图里的卡片位置在子聚合图本身改，上层只挪整个引用。**展开会自动让位，每一层都一样**：任何一层的引用展开后，它在所属画布里的兄弟卡片和本图节点会自动让开、外层虚线框跟着变大（只改显示，不改保存的坐标，折叠即复位），所以排版时每一层仍按折叠卡片留位即可，不要为了展开后不重叠而把卡片拉得很开。
    - **写完运行 `node $S/check-aggregation.mjs --doc <id> --page <id>`**（只读，递归读到最底层），`issues` 里不得有“引用框重叠”“本图节点压在引用框上”“元素超过 50”。它给出的 `frames[].box` 就是编辑器里虚线框的真实位置，可直接用来算下一个引用的落点。
    - 引用 id 仍按 `<聚合图>:<目标>` 起名（如 `tp_identity:m2`）。同一个 id 在多张画布里重复，旧版编辑器会把嵌套镜像混成一个、连线连错卡片；新版已按路径区分，但 `check-aggregation` 仍会提示，新建时不要再重复。

24. **文字节点（标题、说明）不得溢出压图（用户 2026-11-03 截图纠正：标题字太大挡住下面的卡片）**：`text` 节点的字号默认**随节点框放大**（放大倍数 = √(宽×高 ÷ 160×44)，最多 ×3），1700×60 的标题写 `fontSize:22` 实际渲染 66px，换成两三行后溢出到下面的内容上。所以每个 `text` 节点都要写 `data:{textScaleWithNode:false, fontSize:"24"}`（画布标题 24，分区说明 18–20），框高至少是 `行数 × 字号 × 1.4 + 20`，每行字数约为 `(宽 − 16) ÷ 字号`。标题和它下面第一个元素（或引用框顶）之间留 ≥30。写完用 `check-aggregation.mjs`（聚合图）或按这个公式自查，有“文字节点溢出”就改字号或加高，不要靠挪开下面的内容。
25. **引用镜像的交互（每一层都一样）**：聚合图里显示的被引用画布内容是镜像。
    - **编辑**：点选镜像里的节点、连线，以及聚合图画在引用之间的关系线，会打开属性面板；改文字、颜色、样式等会**直接写回它所在的原画布**（关系线写回画它的那张聚合图），所有引用它的地方同步变化。删除、复制、改类型仍到原画布做。镜像元素**不能拖动**（用户确认这样合理）：拖顶层引用里的元素会整块移动这个引用，嵌套层不能拖；要挪位置到原画布挪。跨画布撤销不支持（撤销只管当前画布），改错了就再改回去或到原画布撤销。命令桥只能对原画布 `move` / `update_node`。
    - **折叠与跳转**：每一层引用框标题旁都有 `▸/▾` 和 `↗`；嵌套层的折叠只影响当前聚合图的显示（记在本图 `referenceExpansion`，键是镜像路径如 `ref_a>ref_b`），不改原画布。引用面板的“全部展开 / 全部折叠”覆盖所有层级。鼠标下有多层引用时按 K 弹出层级列表（数字键选、Esc 取消）；父层折叠后子层一起隐藏。
    - **定位**：在建模面板里定位绑定元素时，元素在折叠的引用里会从外到内自动展开路径上的每一层，再选中并定位到那个元素。
    - **流动线**：聚合图画在引用画布之间的关系线（含嵌套层），只要有一端连进已展开的引用画布就自动用流动线显示，和画布内部的连线区分开；两端都是折叠卡片时静止。某条线确实要静止就在原画布给它写 `animated:false`，不要为此改成别的颜色或虚线。
    - **高对比（L）**：鼠标放在某个引用画布上（取最里层）按 L：该画布内部的连线正常显示，它和其他画布之间的连线用动态线高亮，其余连线淡化；再按 L 或 Esc 退出。连线很多的聚合图让用户用它看某个模块的对外交互，不要为了“好看”删减真实的关系线。

26. **设计思想：原子画布 + 自由拼接的聚合图，不画多余的图（用户 2026-11-03 定规）**：
    - **原子画布**：每张只维护一项相对独立的功能，自包含（本功能涉及的对象、第三方、监管都在本图里），原子画布之间不互相引用、不互相依赖。改一项功能只改一张图。
    - **聚合图**只做拼接：引用原子画布（或别的聚合图），用带标签的关系线表达它们之间的业务关系，自己不重画流程、不复制原子画布里已有的节点。
    - **动手前先问“这张图是不是已有内容的另一种看法”**：是就不画。按第三方、按角色、按系统重新切一遍同样的内容，都属于重复维护，改一处就要改多处。确实要换角度时，用建模面板的筛选、分组和条件高亮去看，不新建画布。
    - **建模数据跟着元素走**：记录建在被绑定元素所在的原子画布上并绑定。聚合图会自动继承它引用的所有画布（含引用的引用）的建模数据与绑定，在建模面板里能看到“已绑定”并定位到对应镜像元素，所以**不要把原子画布的表复制到聚合图**，也不要在聚合图上留没有绑定的副本表（用户看到会以为绑定丢了）。
    - 重构时发现多余的视图画布：先把其中独有的数据（如第三方费用明细）迁回对应原子画布并绑定、读回核对，再按规则 13 经用户确认后 `delete_flow`。

27. **改画布内容前必须先升版本并写备注（用户 2026-11-16 定规，全盘适用）**：任何对已有画布的写操作（`apply` 改节点/连线/引用/跨画布线），动手前先给该流程**升一个新版本**，并把本次修改内容写进版本备注，让每次改动都有可回退、可追溯的版本。
    - 命令桥没有升版 op，升版是编辑器 UI 动作：打开目标画布 → 右上角「版本管理」触发器（GitBranch 图标，显示 `vN`）→ 面板里点「升版」。升版会深拷贝当前画布与建模数据到新版本（新 `doc-<uuid>`），旧版本原样保留，`activeVersionId` 指向新版本。
    - 升版后用 `targets.mjs` 读回，找到新 `document_id`（名称与旧版本相同、`node_count` 相同的那个新 docId），**所有写操作只在新版本文档上做**，用它的 `page_id` 和 `read` 到的 `version` 作 `--base-version`。
    - 版本备注：在版本面板里点新版本行的铅笔（重命名），填「vN 日期 本次改了什么」（一句话，含关键决策）。备注存在版本注册表的 `name` 字段，首页与工具栏都会显示。
    - 只有新建画布（`--create`）不需要先升版；新建即 v1。
    - 改完必须复验：`read` 数元素、聚合图跑 `check-aggregation.mjs`，确认 issues 为空再交付。

```bash
S=.agents/skills/huatu/scripts
node $S/targets.mjs                                   # 1 列出可写目标
node $S/catalog.mjs                                   # 2 图库目录（类别、子类、条目 ID）
node $S/read.mjs --doc <document_id> --page <page_id> # 3 读取现状与 version（改已有画布时）
node $S/check-aggregation.mjs --doc <id> --page <id>  # 聚合图写完后的排版自检（重叠、压框、文字溢出、超 50、重复引用 id）
node $S/apply.mjs --doc <id> --page <id> --base-version <version> --ops ops.json [--key <幂等键>]
node $S/apply.mjs --create "采购流程" --ops ops.json [--key <幂等键>]   # 新建画布
node $S/tool.mjs --request action.json [--doc <id> --page <id>] [--base-version <version>] [--key <幂等键>]
```

`apply` 成功返回 `{version, node_count, edge_count, created_ids}`。新建画布用 `--create <名称>`，`ops` 作用于新画布；`create_target` 可省略，若写则必须是第一项且名称与 `--create` 一致。

**菱形、圆、椭圆、六边形永远按正方形渲染**，连接点却在节点外框上；外框不是正方形，线就会悬在图形外面。桥写入这几类图形时会按较短边（最小 140）规整成正方形并保持中心，但仍应直接给正方形尺寸，判断节点用 200×200、字号 16，并给上下节点留足纵向间距（行距 ≥ 260）。

**其他 `tool` 命令**：`{"op":"rename_flow","documentId":"<文档ID>","name":"<新名称>"}`（同名会拒绝）；`delete_flow` 把整个流程移入回收站，`remove_folder` 删除空文件夹，用法见规则 13。

**登记与归档（`tool` 命令 `organize`）**：`{"op":"organize","documentId":"<文档ID>","group":["工作","九洲","系统交互图","00 聚合图"]}`。把画布登记成可被引用的流程，并放进首页分组（路径上缺的文件夹自动创建）。不需要 `--doc/--page`。**默认不执行**（见规则 14，新画布留在「未分组」）；只有用户指定了文件夹，或这张画布要被引用时才做，否则它在首页的“引用画布”面板里选不到。

含中文的命令 JSON 用可靠的文件写入方式明确保存为 UTF-8，例如 Node 的 UTF-8 文件写入。避免把中文放进 PowerShell 5 的 here-string 后通过默认编码管道传给 Python 或其他程序，该路径可能把正文写成问号。提交前解析文件并核对关键中文，写后再用 `read` 和 `modeling_read` 检查原文；文件能解析、命令成功或数量一致均不能证明中文完整。

## 操作（ops.json 是它们的数组，顺序执行，任一失败整批回滚）

| op | 参数 |
|---|---|
| `create_target` | `name`（仅新建画布，且必须是第一项） |
| `add_nodes` | `nodes:[{id?, type?, shape? \| libraryItemId?, label, subLabel?, color?, position?{x,y} \| parent+relative, size?{width,height}, zIndex?(-100..100), data?}]`，type ∈ process/decision/start/end/annotation/text/swimlane/libraryShape；`swimlane` 默认 `zIndex:-1`（在连线和节点下面）；原生 shape：rectangle、rounded、capsule、diamond、hexagon、cylinder、ellipse、parallelogram、circle；其他图形走 libraryShape/libraryItemId。`data` 可设置实际渲染字段如字号，但仍执行绑定与密钥禁写校验 |
| `add_edges` | `edges:[{id?, source, target, label?, sourceHandle?, targetHandle?, type?(default/smoothstep/step), color?, dashed?, waypoints?:[{x,y}], labelPosition?:0..1, labelOffset?:{x,y}, labelFontSize?:10..32}]`，source/target 必须是已存在或本批新增的节点 ID；waypoints 为画布绝对坐标、至少两个点 |
| `update_node` | `id, label?, subLabel?, color?, shape?, size?, zIndex?, data?` |
| `update_edge` | `id, source?, target?, label?, sourceHandle?, targetHandle?, type?, color?, dashed?, waypoints?, labelPosition?, labelOffset?, labelFontSize?, data?` |
| `delete` | `ids?`（节点，连带其连线与子节点）、`edgeIds?` |
| `move` | `ids` + (`dx`/`dy` 或 单个 id 的 `position`) |
| `layout` | `direction?(TB/LR/RL/BT)`, `spacing?(compact/normal/loose)`, `readability?`（默认 true、默认 loose）：保留 ELK 折线、禁止合线、为中文连线标签留位置。会重排全图，只在用户要求整理布局时使用 |
| `set_mindmap_mode` | `mode`（canvas/mindmap）；切换同一画布的视图，原节点坐标、专业图形、业务内容和连线不变。导图按现有有向连线自动排成分支树；循环和多父节点仍保留关系 |
| `set_mindmap_collapsed` | `ids`（已有节点 ID 数组）, `collapsed`（true/false）；折叠或展开分支，不删除后代；多父节点仍可经其他展开的路径显示。仅在导图模式呈现折叠效果 |
| `add_canvas_reference` | `id`（全库唯一，建议 `<本画布>:<目标>`）, `documentId`, `pageId`, `label`, `position:{x,y}`, `expanded?`, `collapsed?`；引用已有画布，**目标画布的内容会真实镜像显示在本画布里的虚线框中**，目标改了这里立即变；`position` 是目标画布原点落点，要让内容左上角落在 (X,Y)，用 `X-内容minX, Y-内容minY`。目标必须已存在、已登记（见 `organize`），禁止循环，同一目标只能引一次。目标里的下一层引用默认按目标画布自身的折叠状态一起镜像显示（与打开目标画布看到的一致）；`expanded:true` 仅用于让本画布折叠的引用在引用面板树里也列出下一层 |
| `update_canvas_reference` | `id`, `label?`, `position?`, `expanded?`, `collapsed?`；移动、折叠/展开已有引用（`collapsed` 折成卡片；下一层引用总是按目标画布自身的折叠状态显示，`expanded` 只影响引用面板树） |
| `remove_canvas_reference` | `id`；移除引用，并删掉连到它的跨画布连线 |
| `add_reference_edge` | `id`, `source:{ref?,object}`, `target:{ref?,object}`, `label?`, `color?(#rrggbb)`, `dashed?`, `labelFontSize?`（10–32）；端点是**节点**：`ref` 为本画布的引用 id，或用 `>` 连接的**镜像路径**（如 `ref_c>ref_m4`，连进被引用聚合图里再引用的画布，最多 6 层）；省略则是本画布自己的节点；`object` 是路径终点画布里的节点 id（会校验存在）。端点画布折叠时自动落到卡片，不用另设锚点节点 |
| `insert_component` | `itemId`（图库条目或个人组件 ID，来自 catalog）, `position?` |
| `add_ink` | `id?, points:[{x,y,p?:0..1}]`（画布坐标、1–2000点）, `tool?`（pen/highlighter）, `color?, size?`（0.5–48）, `opacity?`（0–1）；生成原生可编辑笔迹，可移动、删除、随批次撤销 |
| `insert_asset` | `id?, category`（developer/aws/azure/gcp/cncf/icons）, `itemId`（来自 list_assets）, `position?, label?`；复用资源面板同一目录与图标工厂 |
| `bind_record` | `ids`（已有节点 ID）, `modelId, recordId`（来自 modeling_read）；验证模型与记录属于目标页面后增量绑定，保留已有绑定，随画布事务撤销；先创建画布和真实记录再绑定 |

节点 ID 建议显式给出有意义的 ID（字母数字 `_ . : -`，≤128），连线才能引用；不给则自动生成并在 `created_ids` 返回。坐标用绝对值，分层/分组图可先 `add_nodes` 建分区（type 没有 `section`，只能取上表白名单；分区用 `swimlane` 或图库分组条目），再用 `parent`+`relative` 放入成员。

## 思维导图模式

需要可折叠的导图视图时，先查询 `catalog.capabilities.graph_ops`，确认包含 `set_mindmap_mode` 与 `set_mindmap_collapsed`。用 `add_nodes` 建主题、`add_edges` 建父主题→子主题的连线，再在同一批末尾加入 `{"op":"set_mindmap_mode","mode":"mindmap"}`。例如 `{"op":"set_mindmap_collapsed","ids":["approve"],"collapsed":true}` 折叠 approve 的下级分支；`mode:"canvas"` 恢复原画布坐标与走线。选择原生主题或普通卡片前，按 [画法与检查规则](references/readable-drawing.md) 确认字号与最小尺寸是否适合用户要求。

`read` 和 `apply` 返回 `mindmap:{mode,collapsedNodeIds}`；模式和折叠状态按页保存、计入 version、与本批图形操作一起撤销。切换模式不需要再运行 layout，layout 会修改原画布布局。写后 read 同时核对完整节点/边数量及 mindmap 字段，不把视图暂时隐藏当成节点已删除。底部功能板可手动切换、增加中心主题/子分支和展开全部；节点右侧 +/− 控制各分支。

导图视图会投影节点位置并替换显示走线；`read.nodes.position` 与保存的折线路径仍是原画布数据。当前命令桥未公开投影间距和曲线样式参数：不要声称改了 canvas 坐标就缩紧了导图视图。普通可折叠导图优先用该视图；用户明确要求精确间距、直角分叉或复原特定排版时，可用 `mode:"canvas"` 配合自定义树形坐标与完整 `waypoints`，并说明采用的排版方式。

图库中的单节点条目不一定是 `libraryShape` 类型；使用 `libraryItemId` 时可省略 `type`，由目录模板保留真实类型，例如 `mindmap/central`、`mindmap/topic`。显式传入的 type 必须与模板一致；不要仅因名称含“主题”就强制传 `type:"libraryShape"`。普通圆角卡片和原生导图主题的最小尺寸可能不同，布局时按实际渲染类型计算。

### 导图可读性规则（运筹蛊已内置，作图时按此核对）

- 导图投影默认紧凑：父子间距 52、兄弟间距 12（页面设置可切 normal 72/20、loose 96/32，属于浏览器本地偏好，不进文档、不可撤销、命令桥不能改）。字号按数据渲染，不再固定 14px：正文有效屏幕字号要求 ≥16px，次要说明 ≥14px。
- 可见主题超过 40 个的导图首次进入时从“主干概览”（中心+一级分支）开始，之后恢复用户的阅读位置；“全图总览”是显式动作，缩得很小属于预期，不能拿它判定“字太小”，也不能靠全图适配掩盖正文过小。展开/新增/搜索只定位相关分支，不再次缩放整图。
- 验收字号看**有效屏幕字号**（节点字号 × 当前缩放），不是 `data.fontSize` 数值；投影位置不是 `read.nodes.position`，不要用 canvas 坐标证明导图视图已紧凑。

### 主题命令（编辑器内操作，命令桥无专用 op）

- 添加：选中主题后节点旁加号加子主题（侧边）/同级（下方）；键盘 Tab=子主题、Enter=同级、Shift+Enter=插入父主题（替换原树边为两段，净增 1 节点 1 边）、F2 改名、方向键在父/子/同级间导航；输入框与中文输入法组合输入时不触发。新增是一次可撤销事务并进入文字编辑。
- 整理：同级上下调序、缩进/提升、拖动换父（不可挂到自己的后代）、分支左/右/双向、可编辑大纲（与导图同节点同步，支持搜索定位，会展开必要祖先）。
- 删除有两个不同动作：**删除整分支**（先显示将删除的主题数，一次撤销恢复）与**删除主题、保留子主题**（子主题上提到被删主题的父级）。通过命令桥 `delete` 删除节点会连带其连线与子节点（相当于删整分支），不要把它说成“保留子主题”。
- 折叠：单分支/按层级折叠、折叠后显示隐藏数量、“只看分支”并可返回。折叠只改显示（`set_mindmap_collapsed`），后代仍在 `read` 结果中。
- **同级顺序 = 父节点出边在 edges 数组中的先后顺序**：用 `add_edges` 建树时按希望的阅读顺序依次写入；改顺序只能在编辑器里调序或重写这些边，`move` 不改顺序。

### 导图表达与主题信息（两种模式通用的数据键）

| 内容 | 存放位置与字段 | 命令桥写法 |
|---|---|---|
| 关系线 | 普通边，`data.mindmapRelation:true`（可选 `data.relationLine: dashed/dotted/solid`），标题=边 `label`；不属于树、大纲、顺序 | 先 `add_edges`（`dashed`、`color` 可直接给），再 `update_edge {id, data:{mindmapRelation:true, relationLine:"dashed"}}` |
| 兄弟边界+概要 | 父主题 `data.mindmapBoundaries:[{id, memberIds:[连续兄弟ID], title?, style?(rect/round/dashed), color?, summaryId?}]`；概要是该父主题的普通子主题 | `update_node {id:父, data:{mindmapBoundaries:[…]}}`；概要用 `add_nodes`+`add_edges`(父→概要) 创建后在 `summaryId` 引用 |
| 自由边界+概要（画布模式） | 第一个成员（owner）`data.canvasBoundaries:[{id, memberIds:[任意节点ID], title?, summaryId?}]`；概要是无连线的独立节点 | `update_node {id:owner, data:{canvasBoundaries:[…]}}` |
| 备注/链接/标记 | `data.notes`、`data.topicLink`(http/https/mailto)、`data.topicPriority`(1–5)、`data.topicProgress`(0–100) | `update_node {id, data:{…}}`；清除请用编辑器里的“清除”操作，通过 data 写 null/空值不保证删除该键 |

边界成员 ID 必须是真实存在的节点；`apply` 末尾会清理悬空成员/概要/关系线，清理后以 `read` 为准。边界、概要、关系线、备注等不能通过 Markdown/OPML 往返保留（见下）。

### 导入与导出格式（仅编辑器 UI，命令桥不能创建或导入这些文件）

- 导出菜单：JSON（含页面 mindmap 状态与全部元数据，同级顺序不变、导入不重排版）、Markdown 大纲 (.md)、OPML 2.0、XMind (.xmind)；范围可选整张图或选中分支。资源二进制不打包，只保留引用。
- 导入：.json（替换当前画布，可撤销）、.md/.opml/.xmind（先预览数量与“不会保留的内容”，再写入**新画布**，不修改当前画布）；多工作表 XMind 先选工作表。
- 树形格式只保留标题、层级、同级顺序、网页链接（OPML/XMind 还有纯文本备注，XMind 还有关系线端点+标题）。关系线、边界、概要、样式、业务绑定、树外连线、多父/环节点按名称和数量列在转换报告里；XMind 边界/概要/样式未经真实 XMind 客户端样本核验，不承诺。旧版 XML、加密、损坏或缺 content.json 的 .xmind 会被明确拒绝。
- 用户要“导出给别人用的导图”时先说明报告里会丢什么；需要保真往返时用原生 JSON。

## 常见错误码

`no_live_editor`（工作站主窗口未在线，检查启动状态与版本，刷新或重启主窗口）、`multiple_editors`（开了多个主窗口，写入被拒：窗口共享存储但内存各自独立，会互相覆盖；让用户只留一个主窗口再试）、`stale_version`（需重新 read）、`base_version_required`、`target_not_found`、`document_not_loaded`（文档或目标面板尚未加载完，等一下再试，绝不写入）、`invalid_command`/`invalid_op`（参数不符合 schema，`op_index` 指出第几项）、`unknown_component`、`layout_failed`、`graph_too_large`（read 结果过大）、`internal_error`、`idempotency_key_reused`（同一 `--key` 用于不同内容，换新 key）、`queue_full`、`unauthorized`、`shape_not_in_catalogue`、`unknown_node`/`unknown_edge`、`duplicate_id`、`too_large`、`persist_failed`/`persist_verification_failed`（保存或读回校验失败，已回滚，状态未改变）。

## 示例（在已有画布加两个节点和两条连线）

```json
[
  {"op":"add_nodes","nodes":[
    {"id":"approve","type":"process","shape":"rounded","label":"经理审批","position":{"x":400,"y":200}},
    {"id":"reject","type":"process","shape":"rounded","label":"退回修改","position":{"x":400,"y":340}}]},
  {"op":"add_edges","edges":[
    {"source":"submit","target":"approve","label":"提交"},
    {"source":"approve","target":"reject","label":"不通过","dashed":true}]}
]
```
